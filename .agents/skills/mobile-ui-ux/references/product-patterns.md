# Patterns from real mobile products (patterns, not pixels)

Read this when: a brief says "like Notion/Linear/Revolut/Uber/Spotify/WhatsApp…", when choosing a convention for a product category (finance, messaging, commerce, maps, media, education, enterprise), or when asked whether a popular consumer pattern fits a utility or enterprise app. Use it to justify choices, never to copy a look.

Evidence quality warning: product UIs change and most product evidence is T3-T4 (company blogs, help pages, press relaying company statements). Tags: VERIFIED = a fetched source states it; SNIPPET = search excerpt only; MEMORY = flagged recall. Treat each product item as "this pattern exists/was used", not "this is current". Research date 2026-10-06. For each pattern the skill states what problem it solves, the principle, when to use it, and when NOT to.

Contents: 1 Cross-product consensus · 2 Pattern table · 3 By category · 4 Patterns to NOT import · 5 Platform fidelity trend · 6 Evidence limits

## 2. Pattern table

| Pattern | Seen in | Principle | Use when | Avoid when |
|---|---|---|---|---|
| Bottom tab bar (3-5) | Slack, Teams, Notion, Linear, Google, SAP | Recognition over recall; one-thumb reach | 3-5 frequent destinations of equal rank | > 5 equal items (sidebar/reorderable bar); single-task apps |
| Non-modal bottom sheet, 3 detents | Uber Base, M3, HIG, Google Maps | Two related surfaces at once; progressive disclosure | Details/results over a map, canvas or list | Multi-step flows, long forms, content needing full attention |
| Modal sheet / dialog split | Uber Base, M3, SAP | Interrupt only when needed | Dialog: 2-3 options, short; sheet: scrolling or reference needed | Routine navigation (SAP) |
| Visible close + gesture dismissal | NN/g, Uber Base, M3 | Swipe is a shortcut; an explicit control is the baseline | Every sheet | Never remove the explicit control |
| Persistent create | Slack, Gmail, Notion, Linear | Reduce time-to-capture | Capture/compose is the main job | Read-only/monitoring apps |
| Mini-player accessory | HIG Music, YouTube, Spotify | Continuity while browsing | Media continues across screens | Short clips that end quickly |
| Swipe row actions + Undo | Gmail, Telegram, Things | Speed for experts | 1-2 frequent actions per side plus a visible twin `[H]` | Gesture is the only path; destructive without undo |
| Undo window instead of confirm | Gmail (5/10/20/30 s) | Recoverability beats interruption | Frequent reversible actions | Money movement, irreversible erasure |
| Optimistic UI + outbox | Linear, WhatsApp | Perceived performance; trust via visible state | Small frequent low-reject edits | Payments, server-validated writes |
| Applied-filter chips | Baymard, SAP | Visibility of system state | Any filtered list | Single-filter lists |
| Full-screen filter form + "Show N" | SAP, Baymard | Batch heavy input, see result count | Many facets | Quick 2-3 filters (inline chips) |
| Sticky summary + CTA | Baymard | Keep the primary action in reach | Long PDP with variants | When it hides total cost or duplicates a visible CTA |
| Quantity stepper replaces Add | Baymard grocery | Confirm state in place | Repeat-add contexts | One-off purchases |
| Fee + rate + total live | Wise (study), Apple Pay | Transparency builds trust | Any paid flow | Never hide mandatory fees |
| Per-use auth for sensitive acts | Android, HIG | Match friction to risk | Transfers, credential change | Low-risk reads (passive biometric) |
| Message status ticks | WhatsApp | Feedback, accountability | Messaging, send flows | When social pressure harms (offer opt-out) |
| Hold-to-record + lock | WhatsApp, Telegram | One-handed capture | Voice/video notes | Without a tap alternative |
| Skeleton (> 1 s) | SAP, Uber | Perceived progress with known layout | Known layout, load > 1 s | Fast loads, unknown layout, actions |
| Infinite scroll | TikTok, feeds | Frictionless browsing | Leisure feeds of homogeneous items | Task/search/compare lists; minors without breaks |
| Streaks + freeze | Duolingo | Habit formation via commitment | Self-chosen voluntary habit | Enterprise, finance, parent apps, guilt copy |
| Role-based task-first IA | SAP, Workday | Show what the job needs | Enterprise mobile | Consumer exploration apps |
| Inline one-tap translation | ClassDojo | Remove the language barrier at the point of reading | Multilingual guardians/users | Legal text where translation is non-binding (add disclaimer) |
| Server-driven layout | Reddit, Monzo | Ship UI without releases | Feeds with frequent layout change | Offline-first or highly interactive screens |

## 3. By category

**Productivity.** *Notion*: bottom bar Home/Search/Inbox/Create; mobile editing drops hover handles and slash commands for a "+" insert menu and a toolbar docked above the keyboard (help pages undated). Rule: expose block operations through a visible keyboard-attached toolbar plus an explicit "+" menu; never depend on hover or a hardware key. *Linear Mobile*: positioned for away-from-keyboard jobs (stay informed, file issues, unblock teammates), not a port; Create Issue reachable everywhere; its Liquid-Glass-era redesign rebuilt the glass without refraction (hurts legibility in dense UIs) and draws solid outlines under Increase Contrast; tab bar customizable beyond five because roles differ. Its instant feel comes from local-first data and optimistic mutations (described by a community reverse-engineering of the web client, not an official statement). *Slack*: 2020 hamburger → bottom bar, 2023 shortened to Home/DMs/Activity and re-organized by user rather than workspace (tab IA changes as features grow: re-test it); swipe-between-conversations only as shortcut. *Teams*: iOS bottom bar Activity/Chat/Calendar/Calls (+ Files on Android), More in the top toolbar not as a tab, reorderable. *Gmail*: undo-send window and configurable swipe actions; M3 Expressive adoption in 2025 (T4 coverage criticizes denser containerized layouts). *Todoist/Things*: natural-language quick add (echo the parsed date/project as chips before commit; no source for the preview principle), share-sheet/widget/quick-settings capture; Things' documented iPhone path starts with a swipe: check a visible route exists.
Rules: companion apps limit mobile to triage/capture/unblock; keep create reachable on every screen; nav chrome should recede; one-field capture flow with NL parsing and chips; rank > 5 destinations by frequency, allow reordering, keep overflow out of the tab bar.

**Finance and trust.** *Wise*: show fee, rate and recipient amount updating live as you type (Lyssna study: n=20, website, vendor-published: Wise 3 min 39 s vs Revolut 7 min 6 s to find the total; 70% vs 30% correct: weak). *Apple Pay HIG*: payment sheet lists card, amount incl. tax/fees, shipping; total "Pay <Business>"; itemized lines; "Amount Pending" when the final amount may change; collect size/color/quantity before the sheet; don't force account creation before purchase; don't hide or disable the button (explain unavailability after tap); button ≥ 100×30pt. *Biometrics* (Android BiometricPrompt, HIG): default requires an explicit confirmation tap after biometric success (right for purchases); `setConfirmationRequired(false)` for low-risk re-auth; DEVICE_CREDENTIAL fallback; label "Sign in with Face ID" only for the biometry the device has; no in-app biometric toggle; never "passcode". *Monzo*: merchant-first rows (name, location, logo), unified home timeline with account badges, upcoming bills collapsed into one item, de-duplicated internal transfers, stable ordering despite late-arriving data, user corrections of merchant data, server-decided layout, paginated feed. *Apple Wallet passes*: collapsed front shows one primary value (balance, event date); fine print on the back; barcodes via API, text not baked into images.
Rules: show amount sent, each fee, rate and total on one screen, updating live, total explicitly labeled; never reveal a mandatory fee at the last step; express payment first; per-use authentication with confirmation for money movement; transaction list leads with the human merchant name, separates pending vs settled, de-duplicates transfers, aggregates predictable future items, paginates; chart headline (one-sentence takeaway) + tabular alternative + tap-through to transactions behind a segment (HIG charting data). No verified source on amount sign/currency formatting here; rely on `Intl` rules in data-dense.md.

**Commerce.** Baymard (e-commerce benchmarks): 78% of mobile sites have poor or mediocre product-list UX; 69% lack all four core sorts (price, rating, best-selling, newest); applied filters as scrolling chips (28% or 20% of sites lack an overview: two benchmark vintages, say "roughly a quarter"); PDP: only 38% of mobile sites reach decent performance (apps 36%), 57% use dropdowns for size, 67% give no shipping estimate, 81% lack unit pricing; keyboard removes ~40% of the viewport at checkout; users are interrupted on average every ~20 minutes (some every 4.5) so forms must not lose data and carts persist; unintended taps come from small hit areas, not "fat fingers"; grocery add-to-cart becomes an editable quantity control in place. Sticky add-to-cart summary: appears only once the inline CTA leaves the viewport; never a license to hide the total cost. Conversion-lift claims (5-15%) from vendor blogs are not independent: don't use.
Rules: applied-filter chips always visible; ≤ ~6 quick filters inline `[H]`; heavy filters in a full-screen sheet with a live "Show N results" button; four core sorts; size options as visible buttons; shipping estimate on the PDP; autosave drafts.

**Social.** Instagram's 2025 tab experiment put Reels and DMs first because they drove growth (T4 relaying Meta): IA optimized for one feed's engagement; do not copy into utility/enterprise apps. Infinite scroll: NN/g says fits aimless browsing of homogeneous items and hurts goal-directed finding/comparison/refinding; a "Load more" button restores footer access and signals the end; always restore scroll position. The European Commission's preliminary finding (2026-02-06, not final) says TikTok's infinite scroll, autoplay, push notifications and highly personalized recommender can push users into compulsive "autopilot" use; it suggests disabling infinite scroll over time and adding effective screen-time breaks. Reddit: one-tap jump between content and comments plus a sticky context bar; server-driven feed cells (~12% faster feed loads; presentation logic moves to the server). Rules: task screens (search, compare, review, approve, transact) use pagination or Load more with position restore; leisure feeds only, with visible end/break affordances if serving minors.

**Communication.** WhatsApp (Help Center): one check = sent, two = delivered, two blue = read, clock = not yet sent; in groups blue when all read; Message info screen lists delivered/read/played; read receipts can be turned off (not for groups/voice played); editing resets receipts. Model states pending (clock) → sent → delivered → read, render each distinctly (check count differs: not color alone), expose per-message detail, offer a read-receipt opt-out when social pressure is a concern. Hold-to-record: press and hold, swipe up to lock hands-free, slide left to cancel (video notes capped at 60 s; Telegram similar: lock gestures are SNIPPET). WCAG 2.5.1/2.5.7 and HIG require a non-gesture path: provide tap-to-start/stop or a visible lock button, a visible cancel control, a timer, haptic/visual feedback. Swipe row actions in chat lists (Telegram: right = read/unread, left = pin/mute/delete; swipe to reply): 1-2 high-frequency actions per side, non-destructive first (Telegram ships up to 3; count is judgment), same actions in a visible menu/long-press/edit mode, icon + text, Undo for destructive.

**Travel, maps, mobility.** Sheet over a map with detents (Uber Base, M3, HIG, NN/g agree). Uber Base: collapsed 10-30% of screen height, middle 40-80% (default start), expanded 60 px below the status bar; snaps to the nearest detent; grabber tap cycles detents with a tap area ≥ 48 px high; motion 400 ms, entry cubic-bezier(0.23,1,0.32,1), exit cubic-bezier(0.86,0,0.07,1); narrow screens (< 600) anchor to the bottom at full width, wide screens use side sheets. M3: standard sheets coexist with the main UI; modal sheets cap initial height at 50%; the drag handle needs a single-pointer alternative; predictive back. HIG: large and medium detents. NN/g: Google Maps is the non-modal example; don't stack sheets; always a visible close. Uber's dialog-vs-sheet questions: reference the background? → sheet; 2-3 short options? → dialog; multi-step or long? → sheet/full screen; always include a title, an explicit dismiss, and a button dock. Rule: map/list/canvas + details → non-modal sheet with 3 detents (peek ~15-25%, half ~50%, expanded just under the top), visible grabber with tap-to-cycle and a keyboard/screen-reader path to each detent, snap to the nearest detent, the map reserves an inset equal to the sheet height, a visible close/collapse control. *Airbnb 2022*: category-first discovery (~55-56 categories from ML on titles/captions/reviews over ~4 million homes; the map zooms as categories change) suits browsable inventory but keep a direct search path for known-item users. *Uber rider app 2023*: personalized home, Services tab, Activity hub, lock-screen live trip tracking, optional features behind flags so the core ride-request flow cannot be broken (99.99% availability target). Rule: when the user waits on a physical-world event, surface status where they already look (Live Activity/lock screen/notification) with ETA and a clear next action.

**Media.** Mini-player: HIG tab bar can carry a bottom accessory (Music mini-player) that minimizes inline on scroll and re-expands on tab tap or scroll to top; M3: a standard bottom sheet suits a persistent audio player; YouTube's 2025 floating, resizable miniplayer (T4). Rule: media that continues while navigating keeps a mini-player above the tab bar with play/pause + title + progress, tap to expand to a now-playing sheet, nothing between it and the tab bar, honor audio-session interruptions (HIG playing audio: don't repurpose standard transport controls; distinguish resumable vs non-resumable interruptions). *Netflix*: Smart Downloads deletes the watched episode and fetches the next, opt-in; storage cap 1/3/5 GB and Wi-Fi-only are snippet-level. Rule: automate offline cleanup/prefetch only under explicit opt-in with a visible storage cap and Wi-Fi-only default.

**Education.** *Duolingo*: streaks drive early habit via visible progress and later via loss aversion; company-reported: CURR +21% over four years, daily churn down > 40%, DAU 4.5×, leaderboards +17% learning time; mitigations (Streak Freeze, richer streak animation +1.7% new-learner retention, simplification to one lesson per day, user-chosen commitment). All engagement metrics, not learning outcomes; Duolingo itself notes breaking a streak can demotivate. Rule: a streak must be user-chosen, forgiving, simple and reminder-capped; do not import streaks, leaderboards or guilt copy into parent, student-under-13, employee or money apps. *ClassDojo*: inline one-tap Translate (34 languages at launch, vendor claim: > 22% of US families don't speak English at home; no independent usability research on parent portals found). Rule: for guardian audiences with varied literacy, make translation and plain-language summaries one tap inside the message/announcement, keep the task list short (announcements, messages, attendance/grades at a glance), avoid peer-visible gamified behavior metrics, notify sparingly.

**Enterprise/B2B.** *SAP Fiori for iOS* (T1): five principles (role-based, delightful, coherent, simple, adaptive); role-based = show only what the job needs; hierarchical navigation for deep single-domain data vs flat (tab bar) for multi-domain; modals only for critical acknowledgments; alerts ≤ 2 actions; avoid stacking modal layers. List-report page type: title with a count ("Tasks (100)"); 1-2 icon actions in compact (1-3 regular); search bar always visible or hidden until pull-down; filter feedback bar with tappable applied filters; list cells carry all key info so users can decide without opening; empty-after-filter needs placeholder text; full-screen sort/filter form closing with a results button. *Workday*: inbox → item → action buttons (Approve / Send Back / Deny); newer My Tasks adds bulk approve for eligible items, Simple vs Detailed density, keyword search, filters, sorts (T4 vendor-affiliated). *Salesforce mobile guidance* (T1): avoid horizontally swiping tabs and carousels (content easy to miss; last item reachable in 3-4 swipes); prefer vertical lists or cards; tables collapse to tile lists on narrow screens; never gesture-only; min font 14px; contrast 4.5:1 text, 3:1 icons/large text. Rules: derive tabs from the role's top tasks and hide the rest; inbox/queue = title with count, key decision fields in the row, applied filters as removable chips, heavy filtering in a full-screen form with a results button, explicit handling of empty/filtered-out; approvals: row = requester, type, amount/date, due; detail = summary first with supporting data collapsible; three explicit outcomes (approve, send back with comment, reject); bulk approve only where policy allows (low-risk, uniform items); support delegation and search.

## 4. Patterns to NOT import (trendy-but-weak or context-mismatched)

- Engagement-optimized IA (Instagram's tab order), infinite scroll and autoplay on task screens, streaks/leaderboards/guilt copy in utility or enterprise apps, social-pressure receipts without opt-out.
- Gesture-only shortcuts (swipe-first capture, hold-to-record without a tap path, swipe-to-navigate): hidden, inaccessible, conflict with system edge gestures.
- Auto-hiding chrome that strands the primary action; translucent/glass surfaces behind dense text (Linear skipped refraction for this reason).
- Optimistic UI for payments, irreversible deletes or server-validated writes.
- More than five tabs with an auto "More" (acceptable only with role-based customization and a considered overflow; Linear/Teams are special cases).
- Server-driven UI on offline-first or highly interactive screens.
- Copying M3 Expressive or Liquid Glass styling because a flagship app did it (Google's own adoption was mixed).

## 5. Platform fidelity trend

Shopify announced (2026-09-10) moving the Shop app and others from React Native back to Swift/Kotlin, citing AI coding agents lowering the cost of building twice and wanting fewer layers between code and platform capabilities (iOS and Android at feature parity; business logic decoupled from UI). Linear builds native; Reddit rebuilt with Jetpack Compose and SDUI. This is tooling economics (trend), not a UX rule. Rule: if the stack choice is open, prefer the one with first-class access to platform components (sheets, tab bars, biometrics, Live Activities); if cross-platform, wrap platform primitives rather than re-drawing them. `[T]`
